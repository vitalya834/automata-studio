# Временное тестирование v0.5

[English](TIMED-TESTING.md) | [Русский](TIMED-TESTING.ru.md)

## Область

Лаборатория делает семантику TFSM видимой и исполняемой. Детерминированные
виртуальные часы позволяют выполнить 60-секундную кампанию мгновенно и
воспроизводимо. Затем те же случаи можно запускать на контроллерах через Modbus,
CAN, serial, CLI и другие адаптеры с реальными timestamps.

Поддерживаются `timedGuards`, `timeouts`, `outputDelays` и
`timeoutsAndOutputDelays`. Alur–Dill визуализируется, но не исполняется: для
корректности нужен zone/region engine с несколькими clocks, invariants и reset
sets. Упрощение до одних часов дало бы ложные вердикты.

## Семантика выполнения

- Время монотонно и задано в `timeUnit` модели.
- Timed guard проверяется по времени нахождения в исходном состоянии.
- Тайм-аут состояния срабатывает раньше входа с тем же timestamp.
- Принятый вход сразу меняет состояние и планирует выход по delay contract.
- Задержка бывает точной, интервальной или линейной
  `base + slope * residenceTime`.
- Для воспроизводимости симулятор выбирает середину конечного интервала, а
  оракул принимает любую точку допустимого интервала.

## Генерация тестов

Для каждого конечного endpoint временного guard создаются пробы непосредственно
до, точно на и после границы с учётом открытости интервала. Пробы после тайм-аута
не смешиваются с guards старого состояния.

Для тайм-аута строится access sequence и время переводится на границу. Для
линейной задержки проверяются начало, середина и последняя достижимая часть окна
пребывания в состоянии.

## Вердикты оракула

- `pass` — символ и время удовлетворяют контракту;
- `fail` — неверный выход или принятие перехода;
- `early` / `late` — правильный выход раньше/позже окна;
- `timeout` — ожидаемый выход не появился;
- `invalid` — неоднозначный переход, ошибочная кампания или нет движка.

## От виртуальной модели к контроллеру

```text
TFSM Model IR
  -> временные граничные случаи
  -> адаптер отображает символы в Modbus/CAN/serial
  -> адаптер измеряет фактические наблюдения
  -> временной оракул сравнивает символ и окно задержки
  -> отчёт-доказательство
```

Автомат содержит только абстрактные символы и временные контракты. Например,
`start` отображается в запись Modbus coil, а `running` — в опрос status bit.

## Ограничения

- временная лаборатория пока использует виртуальное время; CLI и Modbus TCP уже
  выполняют обычный Test Plan IR, а wall-clock интеграция временных кампаний ещё
  не подключена;
- нет стохастических распределений времени и параллельных TFSM;
- нет Alur–Dill zone/region execution;
- состояние меняется при принятии входа, а выход может появиться позже; другая
  семантика требует отдельного явно помеченного профиля.
