# Model IR — версии и миграции

[English](MIGRATIONS.md) | [Русский](MIGRATIONS.ru.md)

## Политика версий

`schemaVersion` имеет вид `MAJOR.MINOR`.

- Изменение **MINOR** (`1.0` → `1.1`) обратно совместимо: добавляет только
  необязательные поля или ослабляет правило. Отсутствие нового поля сохраняет
  семантику 1.0.
- Изменение **MAJOR** может нарушать совместимость и требует явной функции
  миграции с предыдущей major-версии.
- Экспериментальные данные хранятся в `extensions` с префиксом `x-` и
  переносятся миграциями без изменения.

Внутри 1.x не меняются оболочка и значения `modelKind`, грамматика ID, контракт
JSON-pointer диагностик, единая `timeUnit` модели и явные границы интервалов.

## Импорт старого `.fsm`

| Старый формат | Model IR v1 |
| --- | --- |
| `machine Name` | `name`, slug в `id`, `modelKind: "mealy"` |
| `initial S` | `initial.stateId` |
| `state S` | `states[].id` |
| `A --in/out--> B` | переход с `input` и `output` |
| `final S` | `x-legacy.finalStates`, так как acceptor не входит в v1 |
| номера строк | `x-legacy.sourceLines`, если нужен round-trip |

Mealy требует выход на каждом переходе, поэтому беззвучный старый переход
получает зарезервированный символ `none`/`ε`. Алфавиты собираются из переходов.
До полноценного анализа импортёр заявляет самый безопасный профиль
`nondeterministic.partial`. Provenance содержит `sourceFormat: "fsm-legacy"`.

## Экспорт в старый `.fsm`

Представимы только Mealy-модели с одним символом выхода. Moore, EFSM и timing
нельзя молча упрощать — экспортёр обязан отказать.
