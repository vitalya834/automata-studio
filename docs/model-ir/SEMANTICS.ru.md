# Model IR v1 — семантика

[English](SEMANTICS.md) | [Русский](SEMANTICS.ru.md)

Каноническая модель обмена Automata Studio. Структуру задаёт
[`schema/automata-model-v1.schema.json`](../../schema/automata-model-v1.schema.json),
runtime-валидатор — [`src/model-ir.ts`](../../src/model-ir.ts). JSON Schema
проверяет структуру, а TypeScript дополнительно проверяет уникальные ID, ссылки
и начальную конфигурацию. Модель v1 корректна тогда и только тогда, когда её
принимает `validateModel`.

## Общая оболочка

| Поле | Значение |
| --- | --- |
| `schemaVersion` | Для этой схемы всегда `"1.0"`. |
| `id` | Стабильный машинный ID модели. |
| `name`, `description` | Человеческие метаданные без семантического веса. |
| `modelKind` | `mealy`, `moore`, `efsm` или `tfsm`. |
| `semanticProfile` | Заявленный deterministic/nondeterministic × complete/partial. |
| `inputAlphabet`, `outputAlphabet` | Типизированные символы модели. |
| `states`, `transitions` | Стабильные ID и структуры конкретного вида. |
| `initial` | Одна явная начальная конфигурация. |
| `provenance` | Инструмент, формат, seed и RFC 3339 timestamp. |
| `extensions` | Расширения с ключами, начинающимися на `x-`. |
| `presentation` | Несемантические координаты графа. |

`semanticProfile` заявляет намерение, но не доказывает свойство — это задача
анализатора. Неизвестные семантические поля отклоняются; будущие данные идут в
`extensions`. Вероятности в v1 запрещены.

ID допускают Unicode-буквы и цифры по шаблону
`^[\p{L}\p{N}_][\p{L}\p{N}_.-]*$`, поэтому кириллица старого `.fsm` сохраняется.

## Виды моделей

### `mealy`

Выход находится на каждом переходе. Недетерминизм и частичность допустимы и
заявляются в `semanticProfile`.

### `moore`

Выход обязателен у состояния и запрещён на переходе. Выход начального состояния
возникает до первого входа.

### `efsm`

Добавляет переменные `bool/int/real/string`, параметры символов, `guard` и
упорядоченный список `updates`. Выражения хранятся как строки с языковым тегом;
v1 не определяет их evaluator. Начальные значения должны соответствовать типам,
updates применяются по порядку после проверки guard.

### `tfsm`

`timeUnit` задаётся один раз на модель. Допустим ровно один профиль:

- `timedGuards` — вход разрешён в `TimeInterval` после входа в состояние;
- `timeouts` — при отсутствии входа состояние беззвучно меняется после `after`;
- `outputDelays` — выход задерживается на constant, interval или
  `base + slope·t`;
- `timeoutsAndOutputDelays` — сочетание тайм-аутов и задержек;
- `alurDill` — clocks, invariants, guards и reset sets классического автомата.

Интервалы имеют явные границы `value + inclusive`; верхняя граница может быть
`unbounded`. Значения конечны и неотрицательны, а точечный интервал требует обе
включённые границы.

## Детерминированность валидации

`validateModel` не изменяет вход и выдаёт одинаково упорядоченные диагностики с
RFC 6901 JSON pointers, например `/transitions/0/to`.

## Вне v1

- вероятностные/стохастические модели;
- statecharts и параллельные регионы;
- выполнение выражений EFSM;
- диагональные clock constraints Alur–Dill;
- композиция и несколько начальных конфигураций;
- проверка заявления `semanticProfile` по отношению переходов.
